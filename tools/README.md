# Παραγωγή PDF και EPUB

Τα `book/workbook_el.md` και `book/workbook_en.md` είναι τα master. Το PDF και
το EPUB είναι παράγωγα — οι διορθώσεις γίνονται πάντα στο markdown, ποτέ στα
παραγόμενα αρχεία.

## Προϋποθέσεις

```bash
pip install weasyprint   # για το PDF
apt install pandoc       # για το EPUB
```

Τίποτα άλλο. Η γραμματοσειρά του PDF ζει μέσα στο `fonts_css.py` ως base64,
οπότε δεν υπάρχουν αρχεία γραμματοσειράς να χαθούν και το PDF δείχνει το ίδιο
σε κάθε συσκευή.

## Εκτέλεση

Από τη ρίζα του repo, τέσσερις εντολές:

```bash
# PDF
python3 tools/build_pdf.py  book/workbook_el.md public/Workbook_el.pdf   book/img/00-cover.jpg
python3 tools/build_pdf.py  book/workbook_en.md public/workbook_en.pdf   book/img/00-cover.jpg

# EPUB
python3 tools/build_epub.py book/workbook_el.md public/workbook_el.epub  book/img/00-cover.jpg
python3 tools/build_epub.py book/workbook_en.md public/workbook_en.epub  book/img/00-cover.jpg
```

Τρία ορίσματα πάντα: το markdown, το αρχείο που θα γραφτεί, το εξώφυλλο.
Η γλώσσα ανιχνεύεται από το ίδιο το κείμενο· δεν δηλώνεται.

Το `build_pdf.py` γράφει και ένα `*_debug.html` δίπλα στο PDF — χρήσιμο για να
δεις τι παρήγαγε ο parser όταν κάτι δεν βγαίνει σωστά. Δεν μπαίνει σε commit.

## Γραμματοσειρά (μόνο για το PDF)

Noto Sans (SIL OFL 1.1), τέσσερα βάρη/στυλ, περιορισμένη στους χαρακτήρες που
εμφανίζονται στο βιβλίο — 18 KB ανά αρχείο αντί για 2 MB.

Τα σύμβολα → ∞ △ ★ ☐ δεν υπάρχουν στη Noto Sans· έρχονται από υποσύνολο της
DejaVu Sans, δηλωμένο ως ξεχωριστή οικογένεια `Symbols` και βαλμένο ως fallback.

Οι υποψήφιες που απορρίφθηκαν και ο λόγος: Atkinson Hyperlegible, Lexend και
OpenDyslexic **δεν έχουν ελληνικά γλυφά** — ελέγχθηκε κατεβάζοντάς τες. Και η
OpenDyslexic δεν έχει τεκμηριωμένο όφελος σε ταχύτητα ή ακρίβεια ανάγνωσης·
αυτό που τεκμηριώνεται είναι το μέγεθος, το διάστιχο και η αριστερή στοίχιση,
που ήδη εφαρμόζονται.

## Γιατί το EPUB δεν έχει ενσωματωμένη γραμματοσειρά

Το EPUB είναι ρέον κείμενο. Ο αναγνώστης επιλέγει μέγεθος και οικογένεια από τη
συσκευή του, και σε βιβλίο προσβασιμότητας θα ήταν λάθος να του το στερήσουμε.
Το CSS ορίζει μόνο ό,τι τεκμηριώνεται: διάστιχο 1,7, αριστερή στοίχιση,
απενεργοποιημένος συλλαβισμός, χώρος ανάμεσα στις παραγράφους.

Για τον ίδιο λόγο αφαιρείται ο χειρόγραφος Πίνακας Περιεχομένων: χωρίς σελίδες,
οι αριθμοί δεν έχουν νόημα. Ο αναγνώστης έχει τον δικό του δυναμικό πίνακα.

## Τι κάνει ο parser του PDF

Σημεία που χρειάστηκαν διόρθωση και δεν είναι προφανή:

- **`unwrap_lines`** — το markdown είναι τυλιγμένο στους 80 χαρακτήρες. Χωρίς
  ένωση, κάθε γραμμή γινόταν ξεχωριστό `<p>` και κάθε `**έμφαση**` που έσπαγε σε
  δύο γραμμές τυπωνόταν με τους αστερίσκους της.
- **Στοιχεία λίστας με συνέχεια** — η δεύτερη γραμμή με εσοχή ενώνεται με το
  στοιχείο, αλλιώς γινόταν χωριστή παράγραφος.
- **Κάρτα τσέπης** — ελέγχεται πριν από τα blockquotes, γιατί στο markdown
  βρίσκεται μέσα σε `>`.
- **Πίνακας Περιεχομένων** — οι αριθμοί σελίδων του markdown αφαιρούνται και
  ξαναϋπολογίζονται με `target-counter`. Δεν χρειάζεται να ενημερώνονται με το
  χέρι, και δεν μπορούν να βγουν εκτός συγχρονισμού.
- **Front matter** — προαιρετικό. Αν λείπει, τα στοιχεία διαβάζονται από τις
  πρώτες επικεφαλίδες του αρχείου.
- **Εικόνες** — `![λεζάντα](img/αρχείο.jpg)`. Δύο διαδοχικές γίνονται ζεύγος
  δίπλα-δίπλα, με ίσο ύψος.
- **Εξώφυλλο** — πλήρους σελίδας, χωρίς κεφαλίδα, υποσέλιδο ή αριθμό. Ο τίτλος,
  ο υπότιτλος και ο συγγραφέας τυπώνονται πάνω στην εικόνα, στο πάνω μέρος όπου
  η εικόνα είναι πιο ήσυχη. Είναι πραγματικό κείμενο, όχι μέρος της εικόνας:
  το PDF παραμένει αναζητήσιμο και προσβάσιμο από αναγνώστες οθόνης.

## Έλεγχος μετά από κάθε build

```bash
pdftotext public/Workbook_el.pdf - | grep -c '\*\*'   # πρέπει να δίνει 0
```

Αν δώσει κάτι άλλο από μηδέν, κάποια έμφαση δεν έκλεισε και οι αστερίσκοι
τυπώθηκαν.
